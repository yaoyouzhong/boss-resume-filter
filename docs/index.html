处理顺序

判断发生在哪里，证据就留在哪里

  1. 01

    配置岗位

    解析招聘需求，核对硬条件、技能权重和配置冲突。

  2. 02

    获取候选人

    读取 BOSS 推荐候选人，或导入猎头、内推等外部简历。

  3. 03

    筛选评估

    先检查硬条件，再计算技能分；AI 只作为可选辅助证据。

  4. 04

    人工复核

    集中处理临界分数、信息缺失和画像冲突。

  5. 05

    联系复盘

    发送前确认，维护回复与跟进，并按岗位复盘误推误杀。

核心能力

不是一个评分按钮，而是一套处理工作台

A / INPUT

候选人获取与简历导入

自动滚动获取 BOSS 推荐候选人；批量导入 PDF、DOCX、旧版 DOC、TXT、MD、RTF 和 HTML 简历。

B / DECISION

规则、AI 与人工复核分层

硬条件先行，技能评分保留拆解；AI 不覆盖明确硬条件，证据不足时进入人工复核。

C / ACTION

联系、跟进与岗位复盘

联系清单发送前确认，结果不明确时暂停；维护回复、约面、下次跟进和岗位反馈样本。

数据边界

默认在本机完成，外部 AI 不是必经路径

简历解析、规则筛选、候选人状态和备份默认保存在本机。启用 AI 能力时，界面显示模型和发送范围；API Key 保存在系统安全凭据中，Codex 登录由本机官方 CLI 管理。

  • 不会自动发送整库候选人数据、备份或 Chrome 登录状态。
  • AI 只补充证据，不替代明确的硬条件与人工决定。
  • 备份 ZIP 当前不加密，应保存到受控目录。
