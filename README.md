# 📋 BOSS 简历筛选器

基于 DrissionPage 的 BOSS 直聘候选人筛选工具，支持招聘需求解析、候选人自动获取、智能筛选、AI 辅助评估、候选人联系、人工反馈、跟进状态、候选人黑名单和数据复盘。

> 当前发布版本：v2.21 岗位配置质量与 AI 解析升级（版本号 v2.21）

## ✨ 功能特性

### 核心功能
- **智能需求解析**: 正则基础解析招聘需求；已配置 AI 时自动增强基本信息、技能关键词、优先项和必要条件，未配置时保持离线正则解析
- **自动获取候选人**: 从 BOSS 直聘推荐页面自动滚动获取候选人信息，支持批量提取和去重
- **多维度智能筛选**: 经验、学历、年龄、薪资范围、工作地点、必要条件等硬条件 + 技能关键词评分模型，自动打分排序
- **AI 智能评估**: 对通过筛选的候选人进行 LLM 二次评估，也可导入完整简历做二次复核，辅助招聘决策
- **筛选结果可解释**: 记录评分拆解、评分解释和关键词命中证据，候选人详情和 Excel 导出都能查看分数来源
- **连续复核工作台**: 分开呈现筛选结论、复核原因和沟通状态，集中查看决策摘要与完整资料，并可连续处理上一位、下一位候选人
- **候选人联系工作台**: 对符合要求的候选人集中确认和发送，支持联系清单持久化、暂停、失败重试及发送结果人工核实
- **候选人待办与状态体检**: 按优先级整理候选人下一步动作，并检查候选人状态是否存在冲突或遗漏
- **人工反馈与跟进闭环**: 支持标记合适、误推、误杀、放弃，维护候选人跟进状态和备注
- **岗位级复盘**: 按岗位汇总结构化反馈原因、误推误杀原因和调整建议，辅助持续优化筛选规则
- **候选人黑名单**: 面试后确认不合适的候选人可加入黑名单，后续扫描、统计和默认 Excel 导出自动屏蔽；结果页主动显示黑名单后导出当前表格时会保留并标明屏蔽状态
- **数据统计看板**: 按岗位查看筛选质量、打招呼效果、反馈结果和跟进转化，支持时间范围过滤
- **Excel 导出**: 自动生成带颜色标识的 Excel 文件（多工作表 + 统计摘要）
- **学历证书核验**: 批量导入毕业证书图片或 PDF，AI 识别姓名、证书编号、学校和专业，通过 Chrome 打开学信网完成批量查询
- **图形界面 + 命令行**: 图形界面侧边栏导航，可视化配置岗位规则、AI 模型、筛选参数；命令行模式支持自动化运行和批量操作
- **跨平台支持**: 支持 Windows 和 macOS

### v2.21 岗位配置质量与 AI 解析升级

**新增功能**

- **配置质量实时检查**：岗位配置页持续展示质量评分及阻断、提醒和建议数量，可通过“查看详情”集中检查条件冲突、遗漏和配置风险
- **未保存内容保护**：编辑岗位配置后，切换岗位、新建岗位、导入配置或离开页面时主动确认处理方式，避免尚未保存的招聘需求和筛选条件意外丢失
- **模型接入自动匹配**：根据服务商、接入地址和 API Key 自动识别适用接口，支持 Kimi Code、通义千问 Token Plan 等不同接入方式

**体验优化**

- **岗位配置页面重构**：重新整理岗位选择、新建和更多操作区域，将“需求来源”调整为“招聘需求”，统一基础筛选条件、技能评分条件和必要条件的页面层级
- **招聘需求收纳优化**：招聘需求支持展开和收起，折叠后显示已保存或已修改状态；编辑后即时刷新配置状态和质量信息，并可恢复已保存内容
- **新建岗位流程优化**：明确填写需求、解析需求、检查结果和保存配置的流程状态，并使用不限制学历、经验、年龄和薪资的初始条件
- **筛选条件编辑优化**：权重输入框支持按钮和鼠标滚轮逐步调整，优化数字对齐、技能名称列宽以及保存、清空、恢复等操作布局
- **AI 解析结果优化**：待确认事项按问题逐条展示，支持自然换行和滚动查看；自动整理职位描述等条目的编号、标点和关系说明，将关系明确显示为“任选其一”或“全部满足”
- **必要条件提取优化**：基础学历和经验要求归入对应筛选条件，“统招本科”等明确限制仍作为必要条件；AI 只补充具有原文依据的条件，不删除已经确认的条件
- **技能条件整理优化**：自动归一化并合并重复技能和别名，区分普通技能与优先项，减少重复记录和重复计分
- **模型状态反馈优化**：默认 AI 模型与学历核验模型使用同一配置时同步连接状态，并优化连接测试和失败原因提示
- **弹窗显示统一**：统一成功、失败、提醒和确认弹窗的字体、按钮、间距及图标；长内容自动滚动，按钮区域保持可见

**问题修复**

- **薪资解析修复**：修复 12k-15k 等月薪范围可能被错误换算为异常数值的问题，并统一元与 K/月的识别规则
- **解析结果回填修复**：修复清空内容、切换岗位或重新解析后，已经失效的后台解析结果仍可能覆盖当前配置的问题
- **模型接入修复**：修复部分 Kimi Code、通义千问套餐及自定义接入地址无法正确获取模型列表、认证或调用的问题
- **学历验证码识别修复**：优化验证码图片清晰度和失败重试；低置信度结果不再自动提交，多次识别失败后转为人工处理
- **简历评估异常修复**：修复简历评估失败时可能丢失原始错误信息的问题，便于查看真实失败原因

### v2.20 候选人联系工作流升级

**新增功能**

- **扫描与联系分离**：图形界面扫描不再直接打招呼；正常完成、达到轮次上限或可能未扫完时，根据运行前选择生成联系清单，并保留本轮结果和范围提示
- **联系清单安全恢复**：筛选完成后统一生成联系清单；程序重启后恢复待发送、发送失败和待核实项目，发送中断的候选人不会自动重发
- **单人和批量联系**：联系候选人工作台支持单选、多选、Ctrl+A 全选和右键联系，可只处理当前选中的候选人，也可统一处理全部待发送人员
- **发送前安全复核**：每次联系前重新检查候选人最新状态、Chrome 登录状态和对应岗位页面；遇到验证码时展示处理明细并等待人工完成，不再适合联系或岗位不一致时安全跳过或保留待发送

**体验优化**

- **工作台操作优化**：精简联系按钮文字，统一右键菜单以及重试、确认等操作样式，并通过悬停提示说明发送准备状态和需要处理的岗位页面
- **结果提示更及时**：联系结束后立即显示本轮结果，较长的加入清单摘要支持滚动查看，确认按钮统一居中显示
- **窗口操作互不干扰**：联系候选人、连续复核、今日待办和数据详情等工作窗口打开时，主界面仍可正常查看和切换；确认和编辑窗口继续保持操作约束
- **状态信息更简洁**：筛选结果状态列只显示必要的业务标记，悬停时补充具体复核原因，减少同一信息重复展示
- **界面提示统一**：将“打招呼队列”“待确认”“失败”等旧称统一调整为“联系候选人”“待核实”“发送失败”，并统一筛选、AI 评估、淘汰记录、扫描范围、更新日志和联系结果等提示

**问题修复**

- **AI 调整说明修复**：运行控制页的 AI 评分说明由 10 分修正为实际使用的 15 分，避免界面说明与评分规则不一致
- **浏览器准备状态修复**：Chrome 已连接且推荐页面就绪后，联系窗口会及时结束“正在连接”提示并展示真实准备状态
- **联系结果弹窗修复**：修复部分结果窗口出现较晚、内容超出后无法查看或缺少可见确认按钮的问题

### v2.19 候选人复核闭环与扫描稳定性

**新增功能**

- **连续复核工作台**：筛选结果支持从当前候选人开始连续查看上一位、下一位；候选人明细分开呈现筛选结论、复核状态和沟通状态，并集中展示判断依据、风险与不足、AI 调整分以及确认、跟进、反馈、简历操作
- **运行前安全确认**：开始扫描前检查岗位配置和当前 BOSS 岗位，严重问题直接阻断、提醒项由用户确认；自动打招呼前展示待发送人数，取消后保留筛选结果
- **本轮结果摘要**：运行结束、停止或异常后集中展示规则筛选、AI 评估、最终保留、主要淘汰原因和扫描范围，明确本轮是否已确认扫描到底
- **待复核原因分组**：今日待办中的待复核候选人可按学历形式、工作经验、求职状态、评分等主要原因展开，方便集中处理同类问题

**体验优化**

- **结果范围选择更直观**：时间范围新增“今天”，结果范围默认“全部记录”，首次进入页面即可看到完整结果
- **今日待办更聚焦**：每位候选人只进入一个优先级最高的任务，“已回复待约面”调整为更准确的“已回复待推进”
- **批量 AI 评估操作更明确**：右键菜单显示本次可评估人数；所选候选人均无需评估时隐藏该操作，混合选择时汇总跳过人数和原因
- **模型用途选择更清晰**：默认 AI 模型和学历核验模型统一在“使用中的模型”中明确选择，并分别显示未检测、测试中、可用或测试失败及原因；API Key 查看入口改为轻量图标
- **操作入口更易识别**：今日待办、查看与复核、候选人状态体检等入口使用语义更明确的高清图标；筛选结果中的黑名单状态简化为无底色的“已屏蔽”

**问题修复**

- **浏览器状态误报修复**：页面刷新或局部重绘时等待并重试，Chrome 关闭或页面连接断开时回到未连接状态；无已发布职位或页面无候选人时跳过不适用的选择器检查
- **重复扫描结果修复**：候选人重新扫描后未通过当前规则时不再沿用旧推荐结果；部分扫描、主动停止或异常中断不会误清理上一次完整扫描保留的待定记录
- **待复核数量和展示范围修复**：筛选结果与今日待办统一判断待复核，不再静默截断结果或待办；发送待确认只影响沟通操作，不再改变原筛选分类
- **Excel 导出范围修复**：严格导出当前岗位、时间、结果范围和屏蔽显示条件下的可见候选人，避免导出与页面所见不一致
- **官方服务识别修复**：结合服务商和接入地址识别官方 API、Token Plan、Coding Plan、Step Plan 等官方套餐入口，不再把官方套餐误判为中转服务
- **候选人岗位记录修复**：同一候选人的 AI 评估、确认、跟进、反馈和移除只影响对应岗位，避免不同岗位记录相互覆盖

## 🚀 快速开始

### 方式一：下载安装包（普通用户推荐）

#### Windows

1. 从 [GitHub Release](https://github.com/yaoyouzhong/boss-resume-filter/releases/latest) 或 [Gitee Release](https://gitee.com/yaoyouzhong/boss-resume-filter/releases) 下载 `BOSS_ResumeFilter.exe`
2. 双击 `BOSS_ResumeFilter.exe` 启动程序
3. 首次使用时，按界面引导完成浏览器连接、岗位配置和系统设置中的模型配置；运行结果可在「筛选结果」和「数据统计」中查看

#### macOS

1. 从 [GitHub Release](https://github.com/yaoyouzhong/boss-resume-filter/releases/latest) 或 [Gitee Release](https://gitee.com/yaoyouzhong/boss-resume-filter/releases) 下载 `BOSS_ResumeFilter.dmg`
2. 双击打开 DMG，将 `BOSS_ResumeFilter.app` 拖到 Applications 文件夹
3. 首次打开时，右键点击 `BOSS_ResumeFilter.app`，选择「打开」，在安全提示中再次点击「打开」
4. 后续可直接双击启动

> 程序启动后会自动检查更新。新电脑首次使用需要在「系统设置」中重新输入 API Key，并选择当前使用的模型。
> 普通用户不需要安装 Python；只有源码运行和命令行模式才需要安装依赖。

### 方式二：源码运行图形界面（开发/调试）

适合需要改代码、排查问题或临时运行源码版本的场景：

```bash
cd boss-resume-filter
pip install -r requirements.txt

# Windows 可双击 gui.bat，或直接运行：
python gui_main.py
```

独立学历证书核验助手：

```bash
python education_tool.py
```

### 方式三：命令行运行（高级用法）

命令行模式适合自动化、批量任务或调试筛选逻辑。普通用户优先使用 EXE/App 图形界面。

#### 1. 安装依赖

```bash
cd boss-resume-filter
pip install -r requirements.txt
```

#### 2. 配置岗位规则

推荐先在图形界面中配置岗位规则。需要批量维护时，也可以直接编辑 `job_config.json`：

```jsonc
{
  // 岗位名称（作为 key，命令行 --job 参数使用）
  "中高级AI工程师": {
    "min_exp": 4,                    // 最低工作年限（年）
    "edu": "本科",                    // 最低学历（博士/硕士/本科/大专）
    "max_age": 35,                   // 最大年龄（岁）
    "work_location": "南京",          // 工作地点（支持多城市，用 / 分隔）
    "salary_min": 12,                // 岗位薪资下限（K，候选人期望最低薪资低于此值会被过滤）
    "salary_max": 15,                // 岗位薪资上限（K）
    "keywords": [                    // 技能关键词（用于评分打分）
      {"name": "Spring Cloud", "weight": 2},  // weight 1=普通，2=2倍权重，3=3倍权重
      {"name": "SpringBoot", "weight": 1},
      {"name": "Spring AI", "weight": 2},
      {"name": "MySQL", "weight": 2},
      {"name": "Redis", "weight": 1},
      {"name": "Java", "weight": 1},
      {"name": "Python", "weight": 1},
      {"name": "LLM", "weight": 2},
      {"name": "智能体", "weight": 2},
      {"name": "Langchain", "weight": 2}
    ],
    "required_conditions": [         // 必要条件（不满足则直接淘汰）
      "统招本科"                      // 支持简单匹配、OR、AND 三种模式
    ],
    "greet_template": null,          // 自定义打招呼话术（null 使用默认话术）
    "original_requirement": "..."    // 原始招聘需求文本（GUI 自动填充）
  }
}
```

#### 3. 运行筛选

```bash
# 自动打招呼模式
python bossmaster.py --greet

# 指定岗位
python bossmaster.py --job "高级 Java 工程师" --greet

# 补打招呼（给已匹配但未打招呼的候选人）
python bossmaster.py --re-greet

# 清空历史后重新跑
python bossmaster.py --clear --greet

# 清空历史但保留已打招呼的候选人
python bossmaster.py --clear --keep-greeted --greet

# 指定滚动轮次（减少滚动次数）
python bossmaster.py --greet --rounds 20

# 深度 DOM 扫描（不走 listener/API 结构化补全，滚动 100 轮）
python bossmaster.py --greet --dom-only --rounds 100

# 指定 API 结构化补全预算（只补全 DOM 已出现候选人）
python bossmaster.py --greet --max-candidates 160

# 输出详细评分信息（查看技能匹配详情）
python bossmaster.py --greet --verbose

# AI 辅助评估（对通过筛选的候选人进行 LLM 二次评分）
python bossmaster.py --greet --ai-eval
```

#### 4. 查看结果

程序运行后会生成：
- `candidates_all.json` - 全量候选人数据（累积、去重）
- `candidates_all.xlsx` - Excel 导出文件（多工作表 + 统计摘要）

#### 5. 中断恢复

运行中按 `Ctrl+C` 中断时：
- 自动保存当前进度
- 下次运行时自动跳过已打招呼的候选人
- 已加入黑名单的候选人会按 `geek_id` 跨岗位屏蔽，不再进入评分、AI 评估、自动打招呼、统计和默认 Excel 导出；结果页主动显示黑名单时，可随当前可见结果导出并标明屏蔽状态
- 不会重复发送消息

## 📁 项目结构

```
boss-resume-filter/
├── bossmaster.py         # BOSS 直聘自动筛选主程序（核心）
├── filtering.py          # 纯筛选规则模块（评分、硬条件、薪资/经验/城市解析）
├── llm_eval.py           # LLM 辅助评估模块（prompt 构建、API 调用、批量评估）
├── ai_adapter.py         # 多服务商接口适配与模型能力验证
├── job_ai_parser.py      # 岗位需求 AI 增强解析模块（基于正则初稿补充优化）
├── job_config_diagnostics.py # 岗位配置保存前体检模块
├── candidate_state_diagnostics.py # 候选人状态一致性体检模块
```

## 📊 匹配规则

### 硬条件（一票否决）
| 条件 | 说明 |
|------|------|
| 学历 | ≥ 岗位要求的最低学历；明确自考、成教、函授等非统招学历时淘汰，只有本科层级但缺少统招证据时转人工确认 |
| 工作经验 | ≥ 岗位要求的最低年限；明确应届或年限不足时淘汰，无法确认年限时转人工确认 |
| 年龄 | 候选人年龄不超过岗位配置的上限；未配置或无法识别时不启用年龄过滤 |
| 工作地点 | 候选人城市在配置地点范围内（支持多地点） |
| 薪资范围 | 候选人期望最低薪资 < 岗位薪资上限 + 1K |
| 必要条件 | 简历文本匹配配置的必要关键词（支持简单匹配/OR/AND 三种模式） |
| 技术关键词 | 岗位 keywords 的匹配度（硬约束关键词不能为空） |

### 软条件（加权打分）
采用四维评分模型：基础25 + 技能(0~50) + 经验超额(0~15) + 学历档次(0~10)，区间 25-100 分。

### 推荐指数
| 等级 | 分数 | 操作 |
|------|------|------|
| 强烈推荐 | 75-100 | GUI 可自动加入联系清单；命令行可配置为直接联系 |
| 推荐 | 65-74 | GUI 可随“推荐及以上”加入联系清单；命令行可配置为直接联系 |
| 待定 | 55-64 | 不自动加入联系清单 |

> 开启 AI 辅助评估后，LLM 会对候选人做二次评分（±15 分调整），调整后的分数重算推荐等级，直接影响联系清单或命令行直接联系的决策。

### AI 辅助评估（大模型二次评估）
对通过筛选的候选人（≥55 分）调用 LLM 进行二次评估，辅助招聘决策。

**启用方式：**
- GUI：运行页勾选「启用 AI 辅助评估」开关
- CLI：添加 `--ai-eval` 参数，如 `python bossmaster.py --greet --ai-eval`

**评估流程：**
1. 筛选阶段：对每个候选人进行规则评分（四维评分模型）
2. AI 评估阶段：对通过筛选的候选人（≥55 分）调用 LLM 二次评估
3. 分数调整：LLM 返回调整值（**-15 到 +15 分**），叠加到规则评分上，调整后总分限制在 0-100 分
4. 等级重算：调整后的分数重新计算推荐等级（≥75 强烈推荐, ≥65 推荐, ≥55 待定）
5. 联系决策：GUI 根据所选策略生成联系清单，命令行按参数决定是否直接联系

**评估结果展示：**
- GUI 结果表：新增「AI评估」列，显示调整值（如 +7、-3）
- 候选人详情：显示 AI 评估理由、调整值、原始规则分、使用的模型
- Excel 导出：包含 AI 评估相关字段

**配置说明：**
- 使用已配置的 AI 模型；源码运行时本机模型配置保存在 `api_config.local.json`，发布包使用程序目录下的 `api_config.json`
- 对通过筛选的候选人按规则评分降序评估，默认不再限制 50 人
- 默认并发 5 路；候选人较多时会增加模型调用量和运行时间
- 支持 stop_event 中断，429 限流自动指数退避

### 打招呼逻辑
- 按钮位置：候选人卡片的 `operate-side` 区域
- 按钮文本："继续沟通"（已匹配）、"立即沟通"（新候选人）
- 发送确认：点击后必须看到按钮变为“继续沟通”或明确成功提示，无法确认时进入待核实；连续出现时暂停发送并提示人工核实
- **中断恢复**：中断时兜底保存，中断后不重复
- **去重机制**：基于候选人与岗位组合去重；重复扫描时使用最新评估结果，并保留已有人工反馈、跟进、黑名单和沟通状态
- **结果更新**：结果页按推荐候选人、待复核、淘汰记录分类；发送待核实属于沟通状态，不改变候选人的筛选分类，但会阻止重复加入联系清单。普通待定只保留最近一次完整扫描结果，首次普通淘汰只进入运行摘要，曾经推荐、AI 淘汰或已有业务记录的候选人继续保留供复核

## ⚠️ 注意事项

1. **浏览器要求**: 需要安装 Chrome 浏览器（程序可自动启动 Chrome 并导航到推荐页面）
2. **手动导航**: 如果浏览器未自动导航到推荐页面，请手动导航到 BOSS 直聘推荐页面
3. **网络稳定**: 保持网络连接稳定，避免中断
4. **数据备份**: 程序保存时会生成 `candidates_all.json.bak`，仍建议定期备份 `candidates_all.json`
5. **中文数字支持**: 自动识别"三年"、"十二年"等中文数字格式

## 🔧 故障排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 未找到沟通按钮 | 页面未进入推荐候选人列表，或 BOSS 页面按钮文本变化 | 确认浏览器在对应岗位的推荐页面后重试；若页面结构变化，需更新选择器或代码 |
| 元素没有位置及大小 | DOM 更新导致 | 代码已处理，自动重试 |
| 候选人提取失败 | 页面未加载 | 等待页面完全加载后再运行 |
| Excel 导出失败 | 源码运行时缺少依赖，或安装包文件损坏 | 源码运行先执行 `pip install -r requirements.txt`；安装包异常时重新下载 |
| 重复打招呼 | 历史数据未正确保存或候选人状态异常 | 先确认 `candidates_all.json` 是否正常保存；必要时在图形界面中按岗位清理数据后重新运行 |
| 模型连通性测试失败 | 网络波动、API Key 无效或模型未开通 | 重试 1-2 次；检查 API Key、Base URL 和模型状态；查看日志详情 |
| 模型列表为空 | API 不支持 models 接口 | 手动输入模型名称；或联系服务商确认 |
| 切换模型后 API Key 为空 | 配置未正确保存 | 重新保存模型配置；源码运行检查 api_config.local.json 权限，发布包检查 api_config.json 权限 |
